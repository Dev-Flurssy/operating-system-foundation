DEALLOCATION OF MEMORY

Until now, we have focused on allocating memory to jobs.
Eventually jobs finish execution and their memory must be released.
This process is called Deallocation.

Definition:
Deallocation is the process of returning occupied memory back to the free memory list.

Importance:
• Makes memory available for new jobs
• Prevents memory from becoming full
• Improves memory utilization
• Helps support multiprogramming

Exam Tip:
Allocation = Give memory to a job
Deallocation = Return memory from a job

------------------------------------------------------------
FIXED PARTITION DEALLOCATION

In a Fixed Partition system, deallocation is simple.

When a job finishes:
Step 1: Locate the partition.
Step 2: Change its status from Busy to Free.
Step 3: Update the memory table.

Example:
Before:
Partition 3 = Busy

After:
Partition 3 = Free

Nothing else needs to be changed because partition sizes never change.

------------------------------------------------------------
DYNAMIC PARTITION DEALLOCATION

In a Dynamic Partition system, deallocation is more complicated.

Reason:
Memory blocks have different sizes.
When a job finishes, the operating system tries to combine neighbouring free blocks.
This helps reduce External Fragmentation.

The Memory Manager checks three possible situations:
Case 1: The released block touches ONE free block.
Case 2: The released block is BETWEEN TWO free blocks.
Case 3: The released block touches NO free block.

------------------------------------------------------------
CASE 1 - JOINING TWO FREE BLOCKS

Original Situation

Free List:
Address 4075 → Size 105
Address 5225 → Size 5
Address 6785 → Size 600
Address 7560 → Size 20

Busy Job:
Address 7600 → Size 200

Free Block:
Address 7800 → Size 5

Address 10250 → Size 4050
Address 15125 → Size 230
Address 24500 → Size 1000

Memory Layout:
7560 --------> 20 Free
7600 --------> 200 Busy
7800 --------> 5 Free

Notice:
The busy job starts at 7600.
Its size is 200.

Therefore:
7600 + 200 = 7800
This proves the busy job is directly beside the free block beginning at 7800.

--------------------------------
When the job finishes:

Released Block:
Address = 7600
Size = 200

The system first turns the busy block into a free block:
Address = 7600
Size = 200 Free

Then it checks neighbouring blocks.
Since:
7600 + 200 = 7800
the released block is directly adjacent to the free block at 7800.

Therefore the two blocks are merged:
200 + 5 = 205

New Free Block:
Address = 7600
Size = 205

Why 7600?
The merged block starts at the lowest address of the blocks being merged:
7600 → Size 200
7800 → Size 5

Lowest address = 7600

Note:
The block at 7560 is NOT merged because:
7560 + 20 = 7580
and
7580 ≠ 7600

There is a gap between them, so they are not adjacent.

--------------------------------
Final Free List

Address 4075 → Size 105
Address 5225 → Size 5
Address 6785 → Size 600
Address 7560 → Size 20
Address 7600 → Size 205
Address 10250 → Size 4050
Address 15125 → Size 230
Address 24500 → Size 1000

Calculation:
200 + 5 = 205

Result:
Two neighbouring blocks (7600 and 7800) become one larger free block of size 205, 
while the block at 7560 remains unchanged because it is not adjacent.

------------------------------------------------------------
CASE 2 - JOINING THREE FREE BLOCKS

Original Situation

Free Block:
Address 7560 → Size 20

Busy Job:
Address 7580 → Size 20

Free Block:
Address 7600 → Size 205

Memory Layout:
7560 --------> 20 Free
7580 --------> 20 Busy
7600 --------> 205 Free

How do we know?
First Free Block:
7560 + 20 = 7580
The busy job starts exactly where the first free block ends.

Busy Job:
7580 + 20 = 7600
The second free block starts exactly where the busy job ends.

Therefore:
Free → Busy → Free
Three consecutive blocks exist.

----------------------------
When the middle job finishes:

Released Block:
Address = 7580
Size = 20

The system first changes the busy job into a free block:
Address = 7580
Size = 20 Free

Now three adjacent free blocks exist:
7560 → Size 20 Free
7580 → Size 20 Free
7600 → Size 205 Free

Since:
7560 + 20 = 7580
and
7580 + 20 = 7600
all three blocks are directly adjacent and can be merged.

The system combines:
20 + 20 + 205

Calculation:
20 + 20 + 205 = 245

New Free Block:
Address = 7560
Size = 245

Why 7560?
The merged block starts at the smallest address among all merged blocks.

Blocks being merged:
7560 → Size 20
7580 → Size 20
7600 → Size 205
Smallest address = 7560

----------------------------
Null Entry

The old entry at Address 7600 is no longer needed because its space has been merged into the block starting at 7560.
Instead of deleting the row and rearranging the entire free list, the operating system marks that entry as a Null Entry.

Why Null Entry?
Deleting rows would require moving other records in the list.
A Null Entry keeps the table organized and reduces processing overhead.

----------------------------
Final Free List

Address 7560 → Size 245 Free
Calculation:
20 + 20 + 205 = 245

Result: Three neighbouring blocks become one larger free block of size 245 starting at address 7560.

------------------------------------------------------------
CASE 3 - ISOLATED BLOCK

Notice:
The Free List contains a Null Entry.
No free blocks adjacent to the released block exist.

Therefore:
No merging can occur.

Step 1:
The job at Address 8805, Size 445 finishes.

Step 2: 
The operating system searches the Free List for a Null Entry.

Step 3:
The Null Entry is reused.

The entry becomes:
Address = 8805
Size = 445
Status = Free

Step 4:
The job is removed from the Busy List.

Result:
Because the released block is not adjacent to any free block, it cannot be merged.
Instead, the operating system places it into the Free List by replacing the Null Entry.

----------------------------
When the job finishes:

Released Block:
Address = 8805
Size = 445

The operating system checks both neighbouring blocks.

Left Side:
7805 → Size 1000 Busy

Right Side:
9250 → Size 1000 Busy

Since both neighbouring blocks are busy, no adjacent free block exists.
Therefore: No merging can occur.

Step 1: The job finishes and becomes free.

Address = 8805
Size = 445 Free

Step 2: The operating system searches the Free List for a Null Entry.

Step 3: The Null Entry is reused and updated with:

Address = 8805
Size = 445
Status = Free

Step 4: The job is removed from the Busy List.

Busy List becomes:
7805 → Size 1000 Busy
Null Entry
9250 → Size 1000 Busy

Step 5: The Free List is updated.

The reused Null Entry now contains:
Address = 8805
Size = 445 Free

----------------------------
Final Free List

Address 4075 → Size 105
Address 5225 → Size 5
Address 6785 → Size 600
Address 7560 → Size 245
Address 8805 → Size 445
Address 10250 → Size 4050
Address 15125 → Size 230
Address 24500 → Size 1000

----------------------------
Result:

No neighbouring free block exists, so no merging takes place.
The released block is simply inserted into the Free List by replacing a Null Entry.

Final Entry:
Address 8805 → Size 445 Free

------------------------------------------------------------
HOW ARE THE TABLE VALUES CALCULATED?

Rule: Ending Address = Beginning Address + Block Size

----------------------------
Example 1
Beginning Address = 7600
Size = 200
Ending Address:
7600 + 200 = 7800

Therefore next block starts at 7800.

----------------------------
Example 2
Beginning Address = 7560
Size = 20
Ending Address:
7560 + 20 = 7580

Therefore next block starts at 7580.

----------------------------
Example 3
Beginning Address = 7580
Size = 20
Ending Address:
7580 + 20 = 7600

Therefore next block starts at 7600.
This is how the book determines whether blocks are adjacent.

------------------------------------------------------------
HOW DOES THE SYSTEM KNOW BLOCKS ARE ADJACENT?

Rule: If
Address A + Size A = Address B
Then the two blocks touch.

----------------------------
Example:
7600 + 200 = 7800
The next block starts at 7800.
Therefore:
The blocks are adjacent.

----------------------------
Example:
7560 + 20 = 7580
Adjacent.

----------------------------
Example:
7580 + 20 = 7600
Adjacent.

When blocks are adjacent they can be merged.

------------------------------------------------------------
WHEN DO WE MERGE?

One Free Block + Released Block
Merge Two Blocks

----------------------------
Example:
200 + 5 = 205
Two Free Blocks + Released Block
Merge Three Blocks

----------------------------
Example:
20 + 20 + 205 = 245
No Adjacent Free Blocks
No Merge
Just insert a new Free entry.

------------------------------------------------------------
NULL ENTRY

An empty table row reserved for future use.

Purpose:
• Avoids moving rows
• Simplifies insertion
• Keeps list ordered by address

Example:
Address = Null
Size = Null
Status = Null Entry

When a block becomes free, this row can be reused.
